# 复用已确认的房主导览制作方法

每次制作室内导览，先读本文件。默认复用 `subject-key-curves-v1`，不要另写一套追随路径转弯的摄像头算法。需要更换方法时，先说明原因并对照短样片。本方法来自用户确认的 56 秒房主方案导览；不是所有户型的舒适保证。

## 参考与边界

- 参考视频：`assets/reference-cases/jujian-champagne-pearl/tour/walkthrough.mp4`。
- 逐帧参考：同目录 `tour.json`；拍摄重点及关键帧：`script.md`、`route-config.json`。
- 公共配置：`assets/h5/tour/homeowner-profile.json`；模板：`camera-config-template.json`。
- 公共算法：`scripts/production/camera_gaze.py`，从原案例离线运镜方法提取，不包含房间坐标、家具 ID 或路线次序。
- 参考实际使用 1.6m 视高、76° 水平视角、24fps、无头部晃动、无切镜。56 秒是该案例时长，不能复制到新案例。
- 原案例配置最大转速 32°/秒，最终逐帧实际峰值约 43.3°/秒。配置不等于测量结果，不要把原案例称为严格满足 32°/秒的样本。公共配置的转速/俯仰/步速阈值是保守起点，需要实际测量及视觉审阅，不是行业标准。

## 1. 路线与观看对象分别设计

按“功能 → 观看对象 → 观察位置与角度 → 连接 → 时长”形成章节。
先确定入口、门洞实际通行侧和出口，再串联观察位置。小房间在入口或浅入处能看清就不深入；必须折返时允许错位回程，空间允许时朝出口行走。不要为了消除重复而穿墙或制造不存在的通路。

每个章节写主要观看对象稳定 ID、观察时间窗，以及进房、观察、转出三个视线意图。长柜、洗衣区等只有在本次参观中承担主要功能或被用户明确要求展示时才另列观看对象；选定对象的可见性不能仅用房间访问或地面覆盖代替。不要将全部柜体自动加入必看清单。不要反复介绍同一对象、刻意盯冰箱或白墙、做无必要的阳台绕圈。

### 房东带看的信息取舍

普通全屋参观以首次看房者理解房间用途、空间关系和主要装修效果为目标，不按家具清单逐件介绍。每间房默认选一个整体构图；次要角落、小设备、柜体细节可省略。卫生间、厨房、次卧等小房间在门口或浅入处短看即可；空阳台看空间与开口，不环扫或补齐两侧。需要逐项验收或展示细节时，另设专项视图，不自动加入普通参观路线。

连接段优先朝向前方通路，取消为了累计覆盖率而增加的侧看、回望和补扫。将“观察转向”与折返、门洞转弯所需的“通行转向”分别检查；后者可必要转身，但不能借转身再介绍已看过的房间。关注累计转角及连续同向转动，转速通过不能证明没有多余环扫。

看完后的退出与已看过区域的回程，不再追加观看对象或重复观看时间；在安全步速和转速上限内可比观察段略快。可在观察章节配置 `timingLimits.maximumSpeedMps` 为较低值，连接段沿用较高的全局步速上限；章节限值不得超过全局上限。朝向按画面需要局部调整，不能把某个案例的统一右偏角度推广为所有户型的默认值。

用户给出总时长上限时，作为本案例硬约束。先删次要观看目标、缩短死胡同深入距离，再重新分配时间；不得强行加速、放宽转速或压缩时间掩盖不合理运镜。当前案例小于 60 秒的要求保存在案例配置，不作为所有户型的统一时长。

## 2. 摄像头朝向是独立的连续曲线

新案例填写 `cameraKeys`：有序的 `atStop`、`offsetFrames`、`targetMm:[x,y,z]`；需要控制构图时可写 `yawDegrees`、`pitchDegrees`。标记必须对应当前路线的唯一访问顺序，不能用最近坐标匹配，把去程绑定到回程。

复用算法依次：

1. 为每个观看对象计算随相机位置变化的视线曲线。
2. 展开 ±π 分支；在对象切换时固定同一旋转分支，避免方向突然翻转。
3. 同对象观察区间持续追踪；不同对象之间用 smoothstep 缓入缓出连接。
4. 按秒配置离线平滑，帧率变化时保持相同平滑时间。禁止逐帧追赶产生机械甩头。
5. 记录实际转速、俯仰速度、角加速度、步速、静止情况。不要为了让数值通过而偷偷放宽阈值。

默认从参考的 76° 水平视角、1.6m 视高、零投影偏移开始，不要为了覆盖家具直接扩为 90°、增加全程俯视或晃动。先调整观察位置、目标和适当时间。变化需先比较同机位样片；二维路线确认不包括此后改变的视角和镜头效果。

### 构图修正与参数作用范围

观看对象被近景家具遮挡或画面只剩墙面时，先检查观察距离、站位与门扇通行侧，再调整观看目标、局部朝向和俯仰；不要用大幅摆头或宽视角补偿不合适的站位。必要近景短暂经过不等于失败，持续遮挡、无内容停留和重点物件不可读才需要纠正。

将移动路径、连接段朝向、房间观察朝向、机位高度、俯仰角及视野分开记录。用户要求“房间扫视向左”只作用于对应观察窗口，并平滑接回连接段；要求“镜头向下”先解释为俯仰变化，不自动降低机位。不得累计历史全局偏转，也不得把某个案例的角度设为共享默认值。

进房展示主体，退房面向出口及下一段通路；只有明确遗漏的主要对象才补看，不反复扫同一侧。空间不足时保留必要折返，不强求绕圈。位置圆弧或样条平滑后，重新检查帧间路径、家具、墙体、门扇及身体包络，不能将几何圆滑等同于安全通行。

## 3. 时间按观看与转弯工作量分配

### 先分配观看预算，再计算通行时间

普通房东导览按已确认房间面积、主要家具组合或空间重心、入口构图的可读性，给每个房间单独制定观看预算。大公共空间优先，小功能空间可短看；面积不是唯一权重，不按平方米机械等比例分配。具体秒数范围、面积系数与构图修正保存在案例配置，注明是展示节奏估算，不宣称为行业标准。

观察章节应覆盖“开始看 → 看清主要构图 → 看完”的窗口；进门转向、退出转身及房间连接另列通行章节。不能把慢慢转向出口的时间称为观看时间。固定构图或小幅调整能看清时，保持简短稳定观看，不用环扫填满预算。输出页面列各房间面积、观看预算和实际章节时长，让节奏分配可以核对。

先满足观看预算，再按安全移动与转向工作量计算连接时间；最后核对总时长约束。超时优先减少多余深入和衔接转角，不能靠削掉主要房间的阅读时间或提高转头速度掩盖问题。改变观看目标或时间后，重新检查连续镜头与确认范围。


保留原方法：每个路径段的最小时间，取“距离/步速上限、转头角度/转速上限、俯仰变化/俯仰上限”的最大值；观察章节还需足够阅读时间。平滑速度连接后重新测量，避免平滑或整体压缩导致限值再次超出。

不固定 30/56/60 秒；预算不足时调整观察意图、减少无用扫描或延长时间。连续移动但不强求匀速；转弯和观察缓慢移动，避免突然停止或猛转。连接段先朝前方通路移动，接近实际门洞通行侧再逐渐转向房间。不能沿长距离提前对着门垛或白墙；以当前门扇姿态、避障和短样片决定转向起点，转头与走位配合。

`camera_gaze.py` 默认只改视线、保留时间；使用 `--retime` 或 `h5.py run --config` 时，公共 `distance-yaw-pitch-effort-v1` 工具按三种工作量和章节最小观看时间重新分配节奏。不会压缩计算出的时长去填固定总时长。重采样保留路径起终点、访问顺序，更新章节标记；清除旧时间线与审阅状态，重做帧间碰撞及观看对象审计。阈值或章节意图失败输出诊断并返回退出码 2，不能授予确认。

## 4. 固定制作顺序，避免反复全量渲染

1. 读取最新保存方案并绑定哈希。使用已安装公共方法及配置，填新案例观察目标。
2. 显示最新家具底图上的路线、朝向和视域；二维预览不证明实际三维可见性。
3. 实际网格检查包含帧间路径、门扇姿态和身体包络；按 `h5-quality-gates.md` 建立 subject plan，运行 `audit --subjects`。缺少可见性检查不能仅凭碰撞通过进入正式全量制作。
4. 先渲染最容易失败的转场短片：入户进房、窄门转弯、房间折返、阳台退出、通道连接。看动态播放，静态拼图不能验证眩晕。
5. 制作低成本完整预览，内部实际播放核验节奏、白墙占屏、重复扫视及重点对象。失败先局部修正，不能用 `--preview` 绕过问题直接当最终视频交付。
6. 预览通过后高清全量渲染；核对浏览器 viewport ≥ 实际画布尺寸，检查右侧/底部是否被背景色截断，核对帧数、解码及播放。
7. 保留输出视频与路线哈希、方法版本、实际参数、检查结果及确认范围。新视频仍待用户观看确认。

局部修正优先沿用已确认路径和大部分镜头，只在明确时间窗内改 yaw/pitch，以平滑边缘接回基线。路径或视高改变重做网格检查；朝向、视角、时间改变重做观看对象/动态检查。每次新输出不能继承旧视频的整体视觉确认。

## 调用

模板故意没有坐标，须填当前案例，不能直接生成虚构路径。`atStop` 指输入 `visits` 的零基 frame 索引，或 `stopFrames.frameIndex`；标记偏移后必须在有效帧范围内。

```text
python scripts/production/camera_gaze.py --tour CASE_PATH_TOUR --config CASE_CAMERA_CONFIG --output NEW_CAMERA_TOUR --retime
python scripts/production/h5.py audit --runtime RUNTIME --tour NEW_CAMERA_TOUR --subjects CASE_SUBJECT_PLAN --out NEW_AUDIT --preview --node NODE --playwright-module PLAYWRIGHT --browser CHROME
```

第二条用于诊断阶段，不能自动标为通过或已接受。原案例 `cameraKeys` 可阅读方法与节奏，坐标、门洞、家具目标不能复制到新户型。参考素材不属于新案例输入，也不替代其空间核对。

## 5. 已接入的公共执行约束

- `h5.py run --config` 自动调用公共视线算法、时间分配和章节意图检查；缺少 `cameraKeys`、章节或检查失败时停止，不静默退回路径追随摄像头。既有 `--tour` 是显式输入，不会重新改写其已确认镜头，仍须重新绑定审阅记录。
- 每章声明 `phase:observe|transit`、`from`、`to`、名称。观察章列 `subjects`；同对象再次介绍需要 `repeatReason`。通行章有观察对象需写 `observationReason`，允许必要回望，不把所有侧看都判成错误。
- `tour_tools.py check` 输出每章正向/反向累计转角、显著转向变更次数、角加速度、步速及静止帧。反复摆头没有万能次数阈值；可在章节 `motionReviewLimits` 写经案例审阅的阈值，超限即失败，动态审阅仍必需。
- `tour_tools.py refine` 使用时间窗内的 sin² 角度偏移，窗口外逐帧保持基线，窗口边缘偏移与导数回到零。输入 `windows:[{startSeconds,endSeconds,yawBumpDegrees,pitchBumpDegrees}]`；不自动更换观看对象。修正后重新检查运动、可见性和动态播放，不能继承整体视觉确认。
- 正式全量动画和超过 1280×720 的全量捕获（包括 `--preview`）必须提供 `--preview-review`。Python 入口及直接浏览器适配器都有检查。低分辨率、明确 `--preview` 的全程诊断仍可生成，用于实际观看，不能标为最终已接受视频。
- 审阅记录必须匹配当前路线、方案、几何、渲染器和场景；绑定转弯样片、完整预览、通过的 subject audit 与 mesh audit 的文件哈希。分辨率变化可沿用同一场景审阅，其余画面/镜头变化使记录失效。
- 审阅模板默认 pending/false，不自动签名、不自动通过。由实际看过动态预览的人或执行者填写，记录内部审阅，不冒充用户最终确认。不能把静态拼图、碰撞通过或“允许生成”写成 `paceComfortable:true`。

```text
python scripts/production/tour_tools.py check --tour CAMERA_TOUR --config CAMERA_CONFIG --output NEW_MOTION_REPORT
python scripts/production/tour_tools.py refine --tour BASELINE_TOUR --config LOCAL_WINDOWS --output NEW_REFINED_TOUR
python scripts/production/tour_tools.py review-template --tour CAMERA_TOUR --runtime RUNTIME --output NEW_PREVIEW_REVIEW
python scripts/production/h5.py capture --runtime HD_RUNTIME --tour CAMERA_TOUR --out NEW_HD_CAPTURE --full --preview-review REVIEW --node NODE --playwright-module PLAYWRIGHT --browser CHROME
```

脚本测试验证连接、限值与失效机制；不证明新视频不晕。新户型必须完成自己的动态预览。低成本预览和高清场景需仅有尺寸变化，使用同一套渲染设置与材质。

## 6. 导览交付检查清单

按“最新保存布局 → 路线与朝向预演 → 易失败转场样片 → 完整低成本预览 → 技术核验与观看验收”推进；需要高清时遵循第 4 节的动态预览门槛。路线页和视频读取同一份冻结的路径、朝向及章节数据，不在视频阶段另建路线。修改后重新绑定方案、路线、场景和视频哈希。

- [ ] 当前保存布局与参观底图一致，入口、门洞及门扇姿态有依据。
- [ ] 主次观看目标明确；没有为了覆盖全部角落增加环扫。
- [ ] 小房间不过度深入；连接段没有无意义拍墙停顿。
- [ ] 入房与退房没有重复介绍同一侧；退出及回程节奏平滑、适当紧凑。
- [ ] 局部扫视、俯仰与全局朝向分开配置，没有历史角度叠加。
- [ ] 平滑后的实际路线、身体包络及主要对象可见性检查通过。
- [ ] 画布无裁切，帧连续，帧数、时长与解码一致。
- [ ] 实际连续播放检查眩晕、突转、拖沓、持续遮挡和重点物件可读性。
- [ ] 用户明确确认当前显示视频；记录准确哈希和确认原话。

无法连续播放时保留内部观看审阅 pending，注明真实工具限制，不用抽帧、数值通过或用户同意生成补签。用户仍可明确接受当前视频；该接受单独记录，不补造内部动态审阅，也不自动授予正式质量门槛通过。定稿后停止无明确问题的可选微调。
