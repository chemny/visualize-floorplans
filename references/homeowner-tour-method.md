# 复用已确认的房主导览制作方法

统一规则入口为 `tour-planning-contract.md`；先读契约，再读本文件的方法与历史证据。
每次制作室内导览，复用公共方法。默认复用 `subject-key-curves-v1`，不要另写一套追随路径转弯的摄像头算法。需要更换方法时，先说明原因并对照短样片。本方法来自用户确认的 56 秒房主方案导览；不是所有户型的舒适保证。

## 参考与边界

- 参考视频：`assets/reference-cases/jujian-champagne-pearl/tour/walkthrough.mp4`。
- 逐帧参考：同目录 `tour.json`；拍摄重点及关键帧：`script.md`、`route-config.json`。
- 公共配置：`assets/h5/tour/homeowner-profile.json`；模板：`camera-config-template.json`。
- 公共算法：`scripts/production/camera_gaze.py`，从原案例离线运镜方法提取，不包含房间坐标、家具 ID 或路线次序。
- 参考实际使用 1.6m 视高、76° 水平视角、24fps、无头部晃动、无切镜。56 秒是该案例时长，不能复制到新案例。
- 原案例配置最大转速 32°/秒，最终逐帧实际峰值约 43.3°/秒。配置不等于测量结果，不要把原案例称为严格满足 32°/秒的样本。公共配置的转速/俯仰/步速阈值是保守起点，需要实际测量及视觉审阅，不是行业标准。

## 带看关注点与优先级（先于距离优化）

普通住宅带看默认先建立整体印象，再展示主要居住空间，最后补充其他功能并回到
入户门退出。默认优先级是产品展示策略，不宣称所有购房者有同一偏好或行业唯一
顺序；已知家庭需求、户型入口条件和用户偏好优先。

| 阶段 / tourRole | 观看者在此应弄清的事 | 处理原则 |
|---|---|---|
| public 公共区 | 客餐厅尺度、采光、开口、公共区关系与主要家具尺度 | 入户先揭示公共区；通常客餐厅相邻展示，阳台有意义时连看 |
| primary 主卧套区 | 主卧舒适性、私密性、床边活动、窗、收纳与套卫联系 | 公共区之后展示；收纳和套卫顺路，不能抢占主卧主体时间 |
| secondary 其他卧室 | 房间用途、床柜或书桌组合、可用空间 | 每房一个构图，门口/浅入短看，不逐件扫描 |
| service 辅助功能 | 厨房操作与餐厅联系、公卫出入与基本功能、生活设备 | 结合回程安排；用户特别重视时可显式提前 |

每个观察项写 `viewPurpose`，同时说明用哪个构图/目标表达它。不能以“家具最近”
代替观看目的，也不能把所有柜体、每面墙都列为必看。入户第一印象、公共区向
私密区过渡、主卧与套卫联系、回到门口，是关键连接节点；它们不等同于每件家具
一个章节。公共区缺少可读整体构图时先换站位，而不是加环扫。

`design-tour` 使用每组的 `tourRole` 建立前置顺序，距离优化只能在同级组间进行。
原子 group 用于客餐厅/阳台或主卧套区的连续介绍；组内次序来自当前户型与展示
目的，不能照抄参考案例。主卧先看还是套卫先看也必须按本次主体说明明确填写。
允许用户明确改变默认阶段顺序，需在 brief 里记录理由并重新预演。

完整看房默认 `tourMode: full_tour`：提供当前方案的 `entranceOpeningId` 与明确
门外起止机位，优化距离包含末段回到同一门口的成本。不能在最后一个卧室戛然
结束。门外仅生成有来源说明的相机停靠区域，不虚构实测公共楼道。明确要求室内
片段时才用 `indoor_segment` / `entry_to_interior`。

用户要求紧凑、不停留时，给短观看预算与小幅单向扫视；具体预算由当前案例给出。用 `observationPanDegrees` 控制小幅扫视，避免重新引入左右
往返或360度环扫。不能为了降低连接占比强行补长观看时间；完整进出与短观看会
自然提高连接占比，需在本案例 `choreographyPolicy` 与针对放宽项的 `ruleExceptions` 明示检查
预算和依据。仍检查每段额外转向、近墙遮挡、背行和停滞，不能只看总占比。

本方法的执行口径以 `tour-rule-implementation.md` 和 `homeowner-tour-rules/2` 为准。
旧参数、旧报告及历史验收不能代替当前源码指纹与同源视觉审阅。

## 新案例的公共规划入口

使用 `h5.py design-tour --bundle BUNDLE --brief BRIEF --out NEW_DIR`，或同目录
`design_homeowner_tour.py`，先生成 `tour.json`、`camera-config.json` 与
`design-report.json`，再调用 `route_rehearsal.py`。本入口不捕获或编码视频。
禁止另写按固定两秒追踪路径前方的案例镜头脚本，也不强制添加250mm观看移动。

Brief schema 为 `homeowner-design-brief/1`，包含有来源的 `startPoint`、
`maximumSeconds`、`rooms` 和可选 `groups` / `endRoomId`。每个观察项给出
`roomId`、`name`、`tourRole`、`viewPurpose`、当前家具 `subjectId`、`targetMm`、`viewSeconds`；有门的小房间
给实际 `openingId`，开放区给经过平面核对的 `candidatePoints`，可用
`entryReferencePoint` 优先浅入。目标点应选主要构图的可见部位，不为了展示柜体
最远端强迫深入。字段和坐标必须来自当前方案，未知门窗或未确认通路不能补造。

程序按真实门洞和当前门扇筛选门口/浅入候选，以墙/门扇视线代理排除遮挡，
再比较选定站位之间的实际可走距离。套区成员可用同一 group 保持相邻；最多
12组，用动态规划求给定站位与组约束下的最短顺序，同时保留原顺序距离对照。
这不是全局最优观察点搜索，也不是实际三维可见性证明。

路径继续使用公共 Planner 的避障、简化、圆弧连接；生成前加入少量规划余量，
生成/重新计时后仍按声明的真实人体半径复查每一帧与帧间路径。观察段可站定。
视线关键帧由空间采样的朝向优化产生：同时惩罚过多累计转角、反复转向、近墙
视线和长距离背行倾向，观看开始/结束角作为边界；不按固定秒数追赶路径。仍使用 subject-key-curves-v1 和公共时间分配工具。
须检查退出阶段是否有不合适的长距离背行，二维数值通过不授予三维运镜接受。
转向优化还须检查采样点之间的角度过渡，不只检查关键帧方向；门扇与门垛视线
使用连续射线相交，不能用稀疏步点跳过薄门扇。轻扫方向根据门洞可见区选择，
不要把当前案例的统一左偏推广到每个房间。

`tour_choreography.py` 输出每章累计转头、显著反向扫视、距离、时间和整体连接
占比；保留重复空间边作为诊断，不把必要的死胡同回程一律当成错误。默认检查
起点为连接累计180度、观察多次明显反向、连接占比55%，均不是行业定律。
已接受参考案例也可能触发这些提示；这不能推翻其真实接受记录或自动判断其
画面不合格。新路线出现提示时先解释/修正，并在需要保留必要动作时重新明确
审阅规则及理由，不能为使结果通过静默放宽阈值或填假通过记录。
公共生成报告不合格会返回退出码2；预演展示提示；视频入口重新检查，不因转速
较慢而忽略多余动作。缺少用户确认的预演仍然不能捕获任何视频。

## 1. 路线与观看对象分别设计

按“功能 → 观看对象 → 观察位置与角度 → 连接 → 时长”形成章节。
先确定入口、门洞实际通行侧和出口，再串联观察位置。小房间默认稍微浅入后观看，能看清就不深入；相邻区域代看需明确记录真实站位与理由；必须折返时允许错位回程，空间允许时朝出口行走。不要为了消除重复而穿墙或制造不存在的通路。

每个章节写主要观看对象稳定 ID、观察时间窗，以及进房、观察、转出三个视线意图。长柜、洗衣区等只有在本次参观中承担主要功能或被用户明确要求展示时才另列观看对象；选定对象的可见性不能仅用房间访问或地面覆盖代替。不要将全部柜体自动加入必看清单。不要反复介绍同一对象、刻意盯冰箱或白墙、做无必要的阳台绕圈。

### 房东带看的信息取舍

普通全屋参观以首次看房者理解房间用途、空间关系和主要装修效果为目标，不按家具清单逐件介绍。每间房默认选一个整体构图；次要角落、小设备、柜体细节可省略。卫生间、厨房、次卧等小房间默认浅入处短看；仅有明确相邻代看理由时可在相邻区域表达；空阳台看空间与开口，不环扫或补齐两侧。需要逐项验收或展示细节时，另设专项视图，不自动加入普通参观路线。

连接段优先朝向前方通路，取消为了累计覆盖率而增加的侧看、回望和补扫。将“观察转向”与折返、门洞转弯所需的“通行转向”分别检查；后者可必要转身，但不能借转身再介绍已看过的房间。关注累计转角及连续同向转动，转速通过不能证明没有多余环扫。

看完后的退出与已看过区域的回程，不再追加观看对象或重复观看时间；在安全步速和转速上限内可比观察段略快。可在观察章节配置 `timingLimits.maximumSpeedMps` 为较低值，连接段沿用较高的全局步速上限；章节限值不得超过全局上限。朝向按画面需要局部调整，不能把某个案例的统一右偏角度推广为所有户型的默认值。

用户给出总时长上限时，作为本案例硬约束。先删次要观看目标、缩短死胡同深入距离，再重新分配时间；不得强行加速、放宽转速或压缩时间掩盖不合理运镜。当前案例小于 60 秒的要求保存在案例配置，不作为所有户型的统一时长。

## 2. 摄像头朝向是独立的连续曲线

新案例填写 `cameraKeys`：有序的 `atStop`、`offsetFrames`、`targetMm:[x,y,z]`；需要控制构图时可写 `yawDegrees`、`pitchDegrees`。标记必须对应当前路线的唯一访问顺序，不能用最近坐标匹配，把去程绑定到回程。

复用算法依次：

1. 为每个观看对象计算随相机位置变化的视线曲线。
2. 展开 ±π 分支；在对象切换时固定同一旋转分支，避免方向突然翻转。
3. 同对象观察区间持续追踪；不同对象之间用 smoothstep 缓入缓出连接。
4. 按秒配置离线平滑，帧率变化时保持相同平滑时间。禁止逐帧追赶产生机械甩头。
5. 记录实际转速、俯仰速度、角加速度、步速、静止情况。不要为了让数值通过而偷偷放宽阈值。

默认从参考的 76° 水平视角、1.6m 视高、零投影偏移开始，不要为了覆盖家具直接扩为 90°、增加全程俯视或晃动。先调整观察位置、目标和适当时间。变化需先比较同机位样片；二维路线确认不包括此后改变的视角和镜头效果。

### 构图修正与参数作用范围

观看对象被近景家具遮挡或画面只剩墙面时，先检查观察距离、站位与门扇通行侧，再调整观看目标、局部朝向和俯仰；不要用大幅摆头或宽视角补偿不合适的站位。必要近景短暂经过不等于失败，持续遮挡、无内容停留和重点物件不可读才需要纠正。

将移动路径、连接段朝向、房间观察朝向、机位高度、俯仰角及视野分开记录。用户要求“房间扫视向左”只作用于对应观察窗口，并平滑接回连接段；要求“镜头向下”先解释为俯仰变化，不自动降低机位。不得累计历史全局偏转，也不得把某个案例的角度设为共享默认值。

进房展示主体，退房面向出口及下一段通路；只有明确遗漏的主要对象才补看，不反复扫同一侧。空间不足时保留必要折返，不强求绕圈。位置圆弧或样条平滑后，重新检查帧间路径、家具、墙体、门扇及身体包络，不能将几何圆滑等同于安全通行。

## 3. 时间按观看与转弯工作量分配

### 先分配观看预算，再计算通行时间

普通房东导览按已确认房间面积、主要家具组合或空间重心、入口构图的可读性，给每个房间单独制定观看预算。大公共空间优先，小功能空间可短看；面积不是唯一权重，不按平方米机械等比例分配。具体秒数范围、面积系数与构图修正保存在案例配置，注明是展示节奏估算，不宣称为行业标准。

观察章节应覆盖“开始看 → 看清主要构图 → 看完”的窗口；进门转向、退出转身及房间连接另列通行章节。不能把慢慢转向出口的时间称为观看时间。固定构图或小幅调整能看清时，保持简短稳定观看，不用环扫填满预算。页面显示简洁中文节点及观看时间；面积、预算计算和诊断留在JSON报告，不恢复技术统计卡。

先满足观看预算，再按安全移动与转向工作量计算连接时间；最后核对总时长约束。超时优先减少多余深入和衔接转角，不能靠削掉主要房间的阅读时间或提高转头速度掩盖问题。改变观看目标或时间后，重新检查连续镜头与确认范围。


保留原方法：每个路径段的最小时间，取“距离/步速上限、转头角度/转速上限、俯仰变化/俯仰上限”的最大值；观察章节还需足够阅读时间。平滑速度连接后重新测量，避免平滑或整体压缩导致限值再次超出。

不固定 30/56/60 秒；预算不足时调整观察意图、减少无用扫描或延长时间。连续移动但不强求匀速；转弯和观察缓慢移动，避免突然停止或猛转。连接段先朝前方通路移动，接近实际门洞通行侧再逐渐转向房间。不能沿长距离提前对着门垛或白墙；以当前门扇姿态、避障和短样片决定转向起点，转头与走位配合。

`camera_gaze.py` 默认只改视线、保留时间；使用 `--retime` 或 `h5.py run --config` 时，公共 `distance-yaw-pitch-effort-v1` 工具按三种工作量和章节最小观看时间重新分配节奏。不会压缩计算出的时长去填固定总时长。重采样保留路径起终点、访问顺序，更新章节标记；清除旧时间线与审阅状态，重做帧间碰撞及观看对象审计。阈值或章节意图失败输出诊断并返回退出码 2，不能授予确认。

## 4. 固定制作顺序，避免反复全量渲染

先执行 `route-rehearsal-gate.md`。动线动画及用户确认是任何视频捕获的前置条件，文字顺序确认和静态路线图均不够。

1. 读取最新保存方案并绑定哈希。使用已安装公共方法及配置，填新案例观察目标。
2. 在最新家具底图上播放动态路线：相机位置、独立朝向、视域随真实时间运动；列出到达时间、观看/连接时长和总时长，允许暂停、拖动、1×审阅。用户确认这个确切动画后才继续；超预算先重排。二维预演不证明实际三维可见性。
3. 实际网格检查包含帧间路径、门扇姿态和身体包络；按 `h5-quality-gates.md` 建立 subject plan，运行 `audit --subjects`。缺少可见性检查不能仅凭碰撞通过进入正式全量制作。
4. 先渲染最容易失败的转场短片：入户进房、窄门转弯、房间折返、阳台退出、通道连接。看动态播放，静态拼图不能验证眩晕。
5. 制作低成本完整预览，内部实际播放核验节奏、白墙占屏、重复扫视及重点对象。失败先局部修正，不能用 `--preview` 绕过问题直接当最终视频交付。
6. 预览通过后高清全量渲染；核对浏览器 viewport ≥ 实际画布尺寸，检查右侧/底部是否被背景色截断，核对帧数、解码及播放。
7. 保留输出视频与路线哈希、方法版本、实际参数、检查结果及确认范围。新视频仍待用户观看确认。

局部修正优先沿用已确认路径和大部分镜头，只在明确时间窗内改 yaw/pitch，以平滑边缘接回基线。路径或视高改变重做网格检查；朝向、视角、时间改变重做观看对象/动态检查。每次新输出不能继承旧视频的整体视觉确认。

第二条用于诊断阶段，不能自动标为通过或已接受。原案例 `cameraKeys` 可阅读方法与节奏，坐标、门洞、家具目标不能复制到新户型。参考素材不属于新案例输入，也不替代其空间核对。

## 5. 已接入的公共执行约束

- `h5.py run --config` 自动调用公共视线算法、时间分配和章节意图检查；缺少 `cameraKeys`、章节或检查失败时停止，不静默退回路径追随摄像头。既有 `--tour` 是显式输入，不会重新改写其已确认镜头，仍须重新绑定审阅记录。
- 每章声明 `phase:observe|transit`、`from`、`to`、名称。观察章列 `subjects`；同对象再次介绍需 `ruleExceptions` 精确指向章节、对象并说明原因；旧 `repeatReason` 不授予例外。通行章有观察对象需写 `observationReason`，但该字段不豁免全时间线重复/遮挡检查。正常经过允许，主动返扫仍需修订。
- `tour_tools.py check` 输出每章正向/反向累计转角、显著转向变更次数、角加速度、步速及静止帧。反复摆头没有万能次数阈值；可在章节 `motionReviewLimits` 写经案例审阅的阈值，超限即失败，动态审阅仍必需。
- `tour_tools.py refine` 使用时间窗内的 sin² 角度偏移，窗口外逐帧保持基线，窗口边缘偏移与导数回到零。输入 `windows:[{startSeconds,endSeconds,yawBumpDegrees,pitchBumpDegrees}]`；不自动更换观看对象。修正后重新检查运动、可见性和动态播放，不能继承整体视觉确认。
- 正式全量动画和超过 1280×720 的全量捕获（包括 `--preview`）必须提供 `--preview-review`。Python 入口及直接浏览器适配器都有检查。低分辨率、明确 `--preview` 的全程诊断也必须先提供 `--route-review` 的动线动画确认；不能作为绕过入口，也不能标为最终已接受视频。
- 审阅记录必须匹配当前路线、方案、几何、渲染器和场景；绑定转弯样片、完整预览、通过的 subject audit 与 mesh audit 的文件哈希。分辨率变化可沿用同一场景审阅，其余画面/镜头变化使记录失效。
- 审阅模板默认 pending/false，不自动签名、不自动通过。由实际看过动态预览的人或执行者填写，记录内部审阅，不冒充用户最终确认。不能把静态拼图、碰撞通过或“允许生成”写成 `paceComfortable:true`。

```text
python scripts/production/tour_tools.py check --tour CAMERA_TOUR --config CAMERA_CONFIG --output NEW_MOTION_REPORT
python scripts/production/tour_tools.py refine --tour BASELINE_TOUR --config LOCAL_WINDOWS --output NEW_REFINED_TOUR
python scripts/production/tour_tools.py review-template --tour CAMERA_TOUR --runtime RUNTIME --output NEW_PREVIEW_REVIEW
python scripts/production/h5.py capture --runtime HD_RUNTIME --tour CAMERA_TOUR --out NEW_HD_CAPTURE --full --route-review ROUTE_REVIEW --preview-review REVIEW --node NODE --playwright-module PLAYWRIGHT --browser CHROME
```

脚本测试验证连接、限值与失效机制；不证明新视频不晕。新户型必须完成自己的动态预览。低成本预览和高清场景需仅有尺寸变化，使用同一套渲染设置与材质。

## 6. 导览交付检查清单

按“最新保存布局 → 带时间轴的路线/朝向动画 → 用户确认该动画及节奏 → 易失败转场样片 → 完整低成本预览 → 技术核验与观看验收”推进；需要高清时遵循第 4 节的动态预览门槛。路线页和视频读取同一份冻结的路径、朝向及章节数据，不在视频阶段另建路线。修改后重新绑定方案、路线、场景和视频哈希。

- [ ] 已展示动态路线、相机朝向、时间轴与观看/连接预算，并取得绑定确切动画的用户确认。
- [ ] 当前保存布局与参观底图一致，入口、门洞及门扇姿态有依据。
- [ ] 主次观看目标明确；没有为了覆盖全部角落增加环扫。
- [ ] 小房间不过度深入；连接段没有无意义拍墙停顿。
- [ ] 入房与退房没有重复介绍同一侧；退出及回程节奏平滑、适当紧凑。
- [ ] 局部扫视、俯仰与全局朝向分开配置，没有历史角度叠加。
- [ ] 平滑后的实际路线、身体包络及主要对象可见性检查通过。
- [ ] 画布无裁切，帧连续，帧数、时长与解码一致。
- [ ] 实际连续播放检查眩晕、突转、拖沓、持续遮挡和重点物件可读性。
- [ ] 用户明确确认当前显示视频；记录准确哈希和确认原话。

无法连续播放时保留内部观看审阅 pending，注明真实工具限制，不用抽帧、数值通过或用户同意生成补签。用户仍可明确接受当前视频；该接受单独记录，不补造内部动态审阅，也不自动授予正式质量门槛通过。定稿后停止无明确问题的可选微调。

### 第二个已确认案例

`assets/reference-cases/dimensioned-homeowner-tour/index.html` 保留本次最终视频、路线/镜头配置和简要证据，可用于比较制作方法。具体 57 秒时长、路径、房间偏转和观看预算均为案例参数，不是新户型默认值。该案例由用户明确接受，内部连续播放审阅因工具限制未完成；不得据此宣称通用舒适度保证或完整可复现渲染包。

### 浅看与必要浅入的选择

阳台等附属空间若从相邻公共区就能表达开口、采光和空间联系，优先在公共区边缘
短看，避免深入后原路长距离折返。brief 可显式指定 `observationRegionId` 与
有依据的 `candidatePoints`；房间和家具 ID 仍属于被展示的空间，不能虚构跨墙视线。
厨房等功能空间若门外看不到本次重点（如水槽和地柜），应浅入到可到达且可见的
位置；用 `candidatePointsOnly` 限定已核对候选，`viewTargets` 同时检查多个构图点。
目标要在整个小幅观看范围内保留视场余量，不以“进过厨房”替代“看到操作区”。
单房可覆盖 `observationPanDegrees`，不强制所有房间转同样角度。上述二维视线与
通行检查仍不代替实际三维播放；不得改门扇或移动已确认家具来伪造可见性。

### 提交前两轮自检

提交新预演前至少做“诊断—局部修正—复查”两轮；改差的候选不替换基线。
逐项记录重复介绍/必要回程、持续近墙视线、位置与朝向同时静止、顺序及路径的
优化范围、每房视域遗漏。不能把两轮次数当通过证明；剩余问题必须列明。
覆盖率先用水平视域采样查漏，记录采样步长、遮挡模型及分母，不能把二维地面
覆盖宣称为真实三维可见面积。每个房间须达到当前案例明确配置的覆盖最低值；不得仅为凑数环扫；
重点构图清楚、无无效往返和观看节奏仍需实际播放核验。最短只对声明的候选、
顺序约束和离散规划图成立，不得称全局最优。真实播放被工具拒绝时如实记录
未完成，不能用数值通过冒充已看。

同一视线区域跨两个功能名（如客厅沙发与相邻阳台洗衣区）时，不应机械地各设一个
观看章节。若同一站位/小幅扫视可读，合并为一次构图，取消第二站的接近、观看和
折返。审查目标进入视场的连续时间窗，区分远处自然入镜与刻意重复介绍；不能只
按房间名不同就认定没有重复。具体家具、坐标、合并站位保留在案例 brief 中。

### 当前规则与实现入口

观察点、一次单向观看、完整进出预算、保留观看时长、覆盖最低值、修订工具和
捕获门槛统一见 `tour-planning-contract.md`。历史中先看公共区一侧、回程再补另一侧
的试验方案已淘汰；不再作为生成建议。具体角度、秒数、阈值和坐标留在当前案例。

## 行走与退场朝向

正常行走优先与位移方向保持60°以内；速度超过0.2m/s时，背向行走（夹角超过90°）
持续超过0.5秒由最终帧检查拒绝。镜头转向与路径转弯自然衔接，退场朝向行进方向。
原地观察、低速微调和短暂侧看独立处理。转向工作量纳入连接预算；预算不足
保留冲突，不突破已确认的观看时间/运动限制。详见 `tour-planning-contract.md`。
