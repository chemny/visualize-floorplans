# Blender 整片提速：测量与取舍（1 号户型，RTX 3090，1280×720）

只在一个户型、一块显卡上测过；数值是产品参考，不是标准。换户型或换机器必须重测。

## 1. 每帧耗时构成（64 采样，CPU 降噪，焦散开）

| 部分 | 约耗时 | 依据 |
|---|---|---|
| 光线追踪 | 3.1 秒 | 8 采样 2.06 秒与 64 采样 4.8 秒两点推算，约 0.049 秒/采样 |
| CPU 降噪（OpenImageDenoise） | 约 1.5 秒 | 同为 8 采样，CPU 降噪 2.06 秒，显卡降噪 0.51 秒 |
| 写盘、同步等 | 约 0.1 秒 | 余量 |

## 2. 对比实验（同一段 60 帧，对比整片里这段已渲的帧）

| 设置 | 每帧 | SSIM | 备注 |
|---|---|---|---|
| 基准：64 采样，CPU 降噪 | 4.8 秒 | — | |
| 关焦散、保留场景数据、PNG 压缩 3 | 4.8 秒 | 0.997 | 不加速，画面几乎相同 |
| 64 采样，显卡 OptiX 降噪 | 3.17 秒 | 0.994 | |
| **32 采样，显卡 OptiX 降噪** | **1.65 秒** | **0.992** | 窗玻璃等大片柔和渐变处略有颗粒；帧间无全局闪烁 |
| 自适应采样（16 到 64，阈值 0.02），显卡降噪 | 3.23 秒 | 0.994 | 此场景不减少采样，没有收益 |

## 3. 结论与做法

- 最大单项是 CPU 降噪，换显卡降噪最划算；其次才是采样数。
- 只改“不改变画面”的选项（`persistentData`、`pngCompression`、关焦散）不会提速，别指望它们。
- 自适应采样在这类光源多、画面均匀的室内场景没有收益。
- 换降噪器会改变画面细节，必须出同帧放大对比图给用户；同时做光流闪烁诊断。
- 整片中途不得换质量档；整片前用同一段 5 秒短样验证质量档，用户看过对比后才用。
- 质量配置键：`denoiser: OPTIX`、`persistentData`、`pngCompression`（0 到 100）、`causticsReflective`/`causticsRefractive`。

## 4. 怎么用

- 预设模板：`assets/h5/tour/blender-quality-fast-template.json`（32 采样用的质量档：显卡降噪、关焦散、保留场景数据、PNG 压缩 3）。采样数写在作业里（`samples`），不是在质量档里。用前仍要在新户型上用 5 秒短样验证，不能直接信 1 号的结论。
- 对比工具：`scripts/production/compare_render_quality.py`。用参考帧和候选帧两个文件夹对同一帧算相似度和峰值信噪比（`compare`），再用 `zoom_sheet` 出同一区域放大对比图给用户看；工具只测量，不代替用户判断。
- 流程：同一段 60 帧，参考设置渲一遍，候选设置渲一遍，对比相似度，再对候选做光流闪烁诊断，最后把放大对比图给用户。
