# 历史案例迁移与展示素材

原始户型、已确认布局和旧素材分别保留。先复制案例到新目录，用当前引擎检查和构建；不能改内置参考案例来掩盖兼容问题，也不能沿用旧页面的验收。

## 顺序

1. 绑定源 case 文件哈希和独立案例命名空间。冻结墙、洞口、家具位置/尺寸、选定风格及显式饰面；清空副本中的旧生产批准，不制造新批准。
2. 检查地面归属。超出小缝修补范围时，报告具体缺口多边形；真实门槛/开放口可由案例显式声明连接带，不能扩大容差、删除地面或缩小户型来通过。完成后检查实际平面和三维三角面覆盖。
3. 原始明确存在的窄收口带如果被墙与可用房间隔开，可用 `floorBoundaryPolicy.retainConnections:[{id,maximumWidthMm,reason}]` 保持为独立饰面。只能引用已声明连接带，宽度上限不超过200mm，并逐格检查墙/房间/其他连接带/户型外重叠；不并入房间可用面积或当作通道。普通缺口和新房间孤岛仍拒绝。具体宽度和ID留在案例。
4. 补明确的房间功能、空间归属等元数据，保留固定风格/颜色选择。检查升级后的实际家具、灯体和派生收口变化；新风格外形不是旧效果图的自动验收。灯体厚度/安装高变化需单列，不写成所有几何完全不变。
5. 复核门、柜、座椅及设施动作。缺少机制或操作声明为待核验，不能把旧淋浴外形等同可用入口。交互通过与布局可用分别报告。真实冲突再做有明确范围的修订，保持平面三维同步。
6. 从同一输入生成新平面、三维及实际导出；运行生成页面的交互/地面/风格检查。回归按房间语义和实际组件选择，不写死某一户型房间ID；不能用无匹配目标的空数组证明功能通过。
7. 确认当前布局和风格后才推进路线。旧路线先按当前契约检查，可复用合格段；旧视频、概念图和旧批准不自动迁移。仍遵循路线→镜头预演→静音视频审阅→讲解成片，H5默认、Blender明确选择。

## 原生检查入口

```text
python scripts/production/h5.py case-upgrade-check --source ORIGINAL_CASE --case NEW_CASE --build NEW_BUILD_RECEIPT --out NEW_REPORT
```

此入口只读输入，写独立报告；不修改案例、不构建、不生成视频、不批准。报告分开列出冻结范围变化、地面阻塞和待补证据。可选 `--media-manifest MANIFEST --scheme-sha256 ACTUAL_EXPORTED_SCHEME` 校验展示素材的同源声明。

`case-media-manifest/1` 顶层绑定 `caseId/caseSha256/schemeSha256`；每项有唯一 `id/kind/status`。`current` 项绑定同一案例与实际文件哈希，渲染/路线/视频绑定实际导出方案，视频另绑定tour哈希。`historical` 项保存源案例哈希和表示边界；`pending` 项不能冒填已有成品。文件声明检查不代替实际画面与播放检查。

README展示保留已确认主图。二维/三维演示从当前工作台实录，讲解视频来自独立确认的静音视频；概念效果图标注其概念参考属性。展示清单留在案例证据中，README不堆内部报告、路径或测试话术。测试通过不能代替素材确认，素材确认也不是GitHub推送授权。

回归：`production/test_case_upgrade.py` 覆盖跨案例混用、旧视频冒充当前、文件被改、冻结范围变化及不自动批准；`production/test_floor_boundaries.py` 覆盖明确收口保留和拒绝重叠/大缺口；实际页面使用 `workbench_browser_suite.py` 的相关检查。
