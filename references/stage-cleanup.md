# 阶段性素材清理

这是由 Agent 在任务阶段结束时执行的可选本地维护流程，不是后台服务。只扫描当前明确指定的项目；不安装定时任务、不清空回收站、不自动永久删除、不修改 Git 或远程内容。公共脚本 `scripts/stage_cleanup.py` 仅使用 Python 标准库。

## 触发与保护

在阶段确认、视频完成且核验通过、最终交付确认后，主动检查是否有明显临时素材积累；一个阶段集中报告一次。用户没有授权执行清理时，止于清单。正在保存、生成、渲染或编码时不移动素材；先等待相关进程完成。不要为触发清理伪造阶段确认。

默认保留原图和参考、当前方案及工作台、最终确认图片和视频、图纸、路线/镜头配置、必要运行资源，以及简要来源与验收索引。未知用途和仍被引用的文件不处理。不根据名称里的“旧版”、文件年龄、未被最终页面引用或曾经生成失败，独自判断无用。旧接受记录、来源快照不重写；大文件需要退役时，先核对来源和恢复依赖并另列范围，不能为了删除而删改引用。

脚本只允许清单明确标注 `obsolete` / `temporary` 且附有 `reason` 和 `evidence` 的媒体/临时文件进入候选。其他角色、受保护目录或文件类型保留。未登记文件列为 unclassified，不自动纳入删除。已被替代的中间图、失败样片、完成视频后的渲染帧是可能的候选，不是必然可删文件。

## 清单与检查

复制 `assets/cleanup-inventory-template.json` 到项目外的维护目录，逐项填写实际文件。模板为空，不预填任何用户确认。各字段：

- `stage`：`stage-confirmed` / `video-verified` / `delivery-confirmed`。
- `stageEvidence`：实际阶段完成/确认依据，不是自动审批。
- `items`：`path` 为项目内 POSIX 相对路径；`role` 为 source/reference/current/final/evidence/dependency/obsolete/temporary；附清理理由和核对依据。

扫描会绑定所有项目文件的哈希、大小和修改时间，检查 JSON（含 Unicode 转义）、HTML（含实体和 URL 编码）及常见文本中的文件名引用。任何同名引用都保守保护。JSON 逐文件完整解析并检查解码后的所有字符串和键名，支持最多 256 MiB 的单个 JSON；其他参考文本上限仍为 16 MiB。无效 UTF-8/JSON、重复 JSON 键、非标准常量、超出预算、读取错误或扫描中变化会中止，不静默跳过。逐文件建立文件名引用索引，不将所有大型 JSON 同时存入内存。大型 JSON 仍使用标准库完整解析，并非流式低内存解析；资源不足时停止。扫描不会执行网页或脚本，也不能证明运行时拼接路径、外部服务和其他项目不存在依赖；Agent 还须核对制作包、首尾帧、审阅证据和动态引用。用途不明确保持保护状态。

```text
python scripts/stage_cleanup.py scan --project PROJECT --inventory INVENTORY_JSON --out NEW_PLAN_JSON
```

命令中的占位路径必须换成真实路径。清单与扫描结果应存放项目外，避免自身成为引用或干扰快照。扫描输出候选、保护项、未知项和可清理字节数；不移动项目文件。大项目全文件哈希可能耗时，在阶段边界检查即可，不在每次保存后扫描。

## 批次确认、备份和隔离

展示候选类别、数量、大小、理由、备份位置和隔离位置，再取得本批明确授权。确认绑定 `planSha256`，传入参数只是防止误用清单，不是用户同意的凭据；Agent 不得自动自批。此功能的安装授权不等于授权清理任何已有项目。清单或项目变化后重新扫描、重新确认，不能自动复用旧同意。

```text
python scripts/stage_cleanup.py apply --project PROJECT --inventory INVENTORY_JSON --plan PLAN_JSON --approved-plan-sha256 APPROVED_HASH --backup-dir SEPARATE_BACKUP_DIR
```

- 备份目录必须位于项目外，拒绝符号链接和父子目录重叠。推荐另一磁盘；脚本不会宣称项目外目录一定是独立物理介质。
- 先创建不覆盖的 ZIP（不重压视频），完成 CRC、每个文件 SHA256 和备份文件哈希校验，再重查项目快照。任何失败保留原文件。
- 通过后移入项目 `.cleanup/BATCH/files/`，保留 `journal.json`；UUID 批次不覆盖既有文件。中途失败保留备份和清单，可用恢复命令恢复已移动的部分。
- Agent 必须暂停同项目写入任务；独占锁仅防止本工具并发，不会锁住浏览器或其他程序，不能声称消除了所有竞态。
- 隔离后复查当前页面/工作台/制作包的引用与适用完整性校验。链接或运行失败立即恢复，不用“移动成功”代替成果可用性。
- 隔离保留期至少 7 天；**不会到期自动删除**。本版不提供永久删除命令。以后要永久清理，重新核对范围并取得单独确认。

隔离只移动同盘文件，不释放空间；备份在同盘时还会额外占用空间。报告分别显示候选逻辑大小、备份位置与实际释放空间，不承诺隔离就回收磁盘容量。磁盘不足时停止，不能跳过备份。

## 恢复

```text
python scripts/stage_cleanup.py restore --project PROJECT --batch BATCH_ID
```

恢复前校验隔离文件哈希和原位置。原路径出现新文件时停止，绝不覆盖用户后来保存的成果。备份和恢复记录保留；若隔离文件损坏或丢失，用校验过的备份人工恢复到新目录并检查路径，不能自动解压覆盖工作区。孤立锁、失败备份或无法判断的部分批次保持原状，先报告并诊断，不自动删除或重置。

## 汇报

报告触发阶段、扫描数量、候选/保护/未知项数量和大小、授权范围、备份与隔离批次、核验结果、恢复方式和保留期。对真实项目首次使用先 scan，仅在用户确认该批后 apply。不在 Memory 保存项目路径和候选文件列表。
