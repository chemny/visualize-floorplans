# 全屋参观规划契约

## 正常行走朝向

正常移动面向行进方向，优先将水平视线与位移方向夹角保持在60°以内。最终帧以
速度大于0.2m/s、夹角超过90°且连续超过0.5秒判定持续倒走；停步转身、低速构图
调整和短暂侧看不计入持续倒走。跨章节连续累计，不能改名为 transit/observe 规避。
这些是产品检查阈值，不是行业标准。正常行走时镜头主要朝向行进方向，镜头转向与路径转弯自然衔接；
返回同一路段可以，背朝行进方向持续移动不可以。完整退场朝向由门洞指向门外终点，
不得默认回头看入户门。转身工作量须计入连接预算；时间不够时报告冲突，不以加速
转头、穿墙或悄悄削减已锁观看时间通过。生成后及平滑后均使用最终帧契约复核。

本文件是生成、修订、预演和捕获的统一规则入口。具体房间、坐标、开口、家具ID、
局部角度、完整访问预算、总时长上限与覆盖最低值，都由当前案例配置提供。
历史案例用于理解方法，不把其参数、接受状态或检查结果复制给新户型。

面积口径由案例明确选择。默认硬覆盖最低值继续拦截不足；已经明确选择
`coverageReferencePolicy.mode: reference_not_visual_acceptance` 的案例按
`unified-tour-production.md` 保留逐房参考差额，交由真实画面审阅，不把参考目标重新
解释成硬面积门槛。两种口径均不替代核心功能、真实遮挡、碰撞与运动检查。

## 1. 五层协作关系

### 核心功能完整性

规划前由 `tour_core_targets.py` 按真实布局和 `assets/h5/tour/core-functions.json`
识别主要功能物件；卫生间含实际存在的马桶、洗手台、淋浴/浴缸，卧室、厨房等按
同一能力表识别主要功能。不存在的设施不补造，装饰、五金和主体自动生成子件不增加停点。
目录尚未识别的自定义类型仍须按案例声明目标；目录不替代完整看房的房间范围检查。
目标遗漏在 `tour_contract.py` 独立报告；候选搜索补齐目标并检查全部目标的并集，
`orderedViewTargets` 只指定顺序，不得覆盖其它无顺序的必看目标。不能通过删目标获得通过。
最终网格检查重新从场景识别设施，不信任规划目标清单；每项核心功能在首次连续观看
窗口内须有至少0.5秒连续可辨认画面。可以同框完成，两个互补观察点可共同交代，退出或
以后再经过不补算。保留独立的漏项、遮挡/出画、过小和过短失败，二维面积覆盖不能替代。
Python/JS捕获入口重新核对该清单及采样。几何代理通过后仍需实际画面检查。

| 层级 | 必须输出 | 责任与约束 |
|---|---|---|
| 房间顺序 | `tourRole`、`viewPurpose`、顺序与理由 | 默认公共区→主卧套区→其他卧室→辅助空间；同级再比距离。用户指定顺序优先，跨阶段例外写 `orderOverrideReason` |
| 观察窗口 | 真实 `roomId`、`observationId`、候选站位、目标、扫视方向、第二点理由 | 每房默认一点、最多两点；家具只是观看目标。第二点补足第一点表达不清的重要区域 |
| 可走路径 | 开口、身体半径、真实避障路径 | 稍入房间后观看；避免无用深入。正常退出和后续途经是导航，必要回程允许，不强求零重复路径 |
| 镜头与时间 | 独立朝向、俯仰、视高、视野、逐帧时间线 | 一次连续访问完成房间介绍，单向揭示主要内容；连接提前盯墙、重复摆头、无内容停留需要修正 |
| 验收 | 同源预演、数值报告、真实画面审阅、用户确认 | 三类证据分别记录。数值通过不代表真实三维可见或动态舒适；不自动签署用户批准 |

用户明确指定物件顺序时，把它编排成上述观察窗口中的连续揭示，不给每件家具
各设停点。默认首次访问完成一个房间；不能离开去看其他卧室后再回来补介绍。
同一连续公共区可有两个互补观察窗口，仍需核对真实房间、方向与连续性。
正常退出时允许原房间自然再次入镜，不将其改名为新一轮介绍。

## 2. 产品默认值与案例参数的边界

- 产品默认：每房一个观察点、上限两个；第二点要说明遮挡或独立区域的必要性。
- 当前产品节奏默认：单点推荐1.5–2.5秒、上限3秒；位置和朝向同时不动不超过0.5秒。
  推荐下限不用于制造等待；这些是产品选择，不是行业标准。
- 速度、转速、视高和视角由公共方法配置提供保守起点。局部改角度须明确作用窗口；
  房间朝向、连接朝向、俯仰和视高分别修改，避免历史全局偏转叠加。
- `maximumSeconds`、`coveragePolicy.minimumPercent` 必须在案例中明确填写；共享引擎
  不再为新案例默认填入某个总秒数或覆盖百分比。
- 每房完整进入/观看/退出预算另放 `roomBudgetPolicy`，不能用短观看章代替完整访问计时。
  总时长达标不能抵消某房超时，覆盖达标也不能抵消进出预算失败。
- `coveragePolicy.enabled:false` 只产生诊断输出，不能通过新契约的捕获检查。

## 3. 生成与修订

使用 `h5.py design-tour --bundle --brief --out`。空白输入结构见
`assets/h5/tour/tour-brief-template.json`；先补齐当前案例值才能运行。
生成器默认使用房间展示阶段优先级，固定顺序仍通过契约复查。

观察站位先满足可到达、能表达整体、适度浅入，再比较连接成本。阳台等可从相邻
区域表达的空间，显式声明 `observationRegionId`；不虚构跨墙视线。
观看方向按两侧构图、入口和出口选择；静态整体构图能看清时可零扫角，不为凑数环扫。
第二点不能成为增加第三点、绕圈或分两次参观的理由。

共享工具：

- `refine_tour_connections.py`：只修订指定连接，其余窗口逐帧保留。
- `compact_tour_visits.py`：保留每个观察窗口时长，允许安全短步与观看重叠。
- `viewingDurationFloors`：保存原有逐窗口时间下限；多次修订后继续继承，删除窗口
  或缩短任一窗口都会报错，不能只保证观察总秒数相等。

移动观察仍是一个连续窗口，不把避障顶点算成观察点，也不把新增家具停点假称为
`movingView`。移动延续必须有相邻同房间、同过程的观察窗口及真实位移。
移动构图的家具可读性必须在后续三维画面中核验。

路径圆弧化后检查身体包络；A*网格节点必须与精确机位真实连通，不能直接替换
端点制造穿墙。重计时后检查每帧与帧间连线。零距离连接若需转向，分配真实转向帧，
不能发生角度跳变。超时优先改站位、深入、冗余转向及连接，不提高既有运动上限、
压缩用户要求保留的观看时长、降低覆盖要求或挪动冻结家具/门扇。

## 4. 一个契约，多个入口

`scripts/production/tour_contract.py` 在最终帧上统一检查：

1. 方案身份、时间线分区、帧数与总时长一致；完整参观返回同一已确认入口。
2. 真实身体包络、圆弧和帧间路径安全；实际步速、转速和俯仰速度符合当前限值。
3. 真实房间的一次连续介绍、展示阶段例外理由、观察目的、单向扫视和重复家具介绍。
   相邻移动段与观察点的同对象连续可见属于一次延续；其他重复介绍需要明确专项理由。
4. 观察点数量、第二点理由、单点时长、伪装移动停点和长时间同时静止。
5. 每个受保护观察窗口的观看时间下限。
6. 按案例最低值逐房检查完整多边形水平覆盖；保留网格、采样和遮挡模型边界。
7. 每房完整进出预算及案例总时长上限。

生成器、连接/移动观察修订、`h5.py run --config` 与预演使用同一检查模块；Python
捕获入口在确认及哈希检查后重新计算。直接浏览器捕获读取同源预演生成并由哈希
绑定的契约报告，存在失败或缺少报告就拒绝，不只检查总时长。

独立只读审计：

```text
python scripts/production/tour_contract.py --bundle BUNDLE --tour TOUR --config CONFIG --out NEW_REPORT
```

所有路径由当前任务填入。脚本只写新报告，不生成视频；检查未通过返回退出码2。
报告状态 `numeric_pass_visual_pending` 仅代表这些数值门槛通过；真实3D可见性、动态
舒适度和用户接受仍为pending。旧配置可读取，但报告为 `legacy_not_contracted`，
不能称为已经通过这套新契约；移入新流程时补齐案例策略并重新生成预演。

## 5. 预演与交付

同一份冻结逐帧数据驱动二维预演与后续视频。页面保留简洁的中文节点、路径、
镜头视野和播放控制；覆盖、累计转头、英文ID、连接占比等技术细节留在JSON报告。
先内部诊断、局部修正并复查；未解决的冲突明确保留待调整，不能把迭代次数当通过。

展示确切预演后，由用户确认路径、朝向及节奏，按
`route-rehearsal-gate.md` 绑定哈希。随后才可按用户授权制作风险转场样片、完整低成本
三维预览及正式视频。实际连续播放需检查拍墙、遮挡、重复介绍、突转和眩晕；
静态图、二维覆盖和运动数值不能替代该步骤。修改导致旧证据失效时重新审阅。

不在Memory中保存案例坐标、引擎代码、临时故障、候选路径或尚未验证的舒适度结论。
个例数据和未解决冲突保留在案例brief/config、检查报告与任务记录中。

## 6. 三轮审计补齐的执行约束

- `orderedViewTargets` 必须解析为当前冻结方案的真实家具或显式开口ID；
  不能只复制到章元数据。生成器用其实际位置确定起始朝向和单向扫角；目标顺序
  要求折返或超过半圈时拒绝，要求换站位/目标，不能自动绕一圈补齐。
- 最终帧再核对目标在观看窗口内的水平无遮挡时间和顺序；缺失对象、被挡、时长不足
  或顺序错误都会失败。窗套/开口的自身宿主墙不算挡住自己，其他墙与门扇仍参与检查。
  普通 `subjects` 也检查可见性，但不虚构用户未指定的先后顺序。
- 单向性按真实 `roomId` 汇总整个连续介绍及两个窗口间的朝向衔接；不能把来回扫
  切成两个各自单向的章骗过检查。退出/后续途经的 `transit` 正常路过不算第二次介绍，但主动返扫、近景遮挡仍在全时间线检查范围。
  历史缺少房间ID的章标记为不可汇总，不能把它们合并成一个虚构房间。
- `tour_camera_evidence.py` 对全时间线检查持续近墙视角和最终采样的转向/俯仰加速度，
  包含连接、退出和章节边界。产品初始审查阈值：五条水平射线中至少四条在900mm内
  撞墙、连续超过1秒则需修订；偏航加速度240°/s²、俯仰120°/s²；目标水平可见时间
  至少0.25秒。阈值是保守产品选择，不是行业标准或舒适度证明。
  `cameraEvidencePolicy` 可由案例明确设置；放宽须写 `ruleExceptions` 中的
  `camera_evidence_limit_override` 及具体依据；旧 `cameraEvidenceOverrideReason` 不再授予放行。
- 局部连接工具保留精确端点，不能对连接单独平滑后制造与房间边界的角度跳变。
  局部工具的未平滑中间采样不构成豁免：最终全局加速度检查失败就不能捕获。
- 旧配置缺少 `tourContract` 时只可诊断/迁移，Python、浏览器直接捕获和
  `h5.py run --config` 均拒绝放行。旧版数值报告缺少最新 `cameraEvidence` 也不能沿用。
- Blender动画的两条直接入口暂时禁用，直到接入同源路径批准和动态样片关卡；
  不能把尚未接入关卡说成支持已验收动画。Blender静态出图继续可用。
- 正式H5捕获还要把真实mesh subject-audit的采样与这份路径的观察章、目标和顺序
  对齐；不能用遗漏所需目标的另一份通过报告替代。该核对同时落实到Python和JS入口。
  真正的连续观看舒适度仍必须由实际播放与审阅确认。

跨案例只读复核使用 `scripts/production/audit_tour_case_matrix.py --manifest CASE_MATRIX --out NEW_DIRECTORY`。
manifest逐案指定 `tour`、`config` 和 `bundle`，或相同scheme哈希的 `scene`，或原始`case`+`state`。
同时输出原始章时长、正反转角、路径长度、目标窗口、拍墙段、加速度峰值以及在真实轨迹副本
注入故障后的拦截证据。历史用户定稿、当前新规则、缺少元数据和未做三维播放必须分开记载。
任何案例的旧视频、旧确认、布局和参数均不得为通过复核而覆盖或改松。


## 7. 统一候选选优与自动修正

新制作和现有路线修订先执行 `unified-tour-production.md`。`h5.py plan-tour --job --out`
统一绑定输入、候选站位/路径/镜头联合比较、故障定位与有界修正，再交路线预演及另存的真实三维检查页面；三阶段呈现遵循 `tour-presentation-pages.md`。
候选搜索和角度投影不是新的验收豁免；全部最终检查继续生效。没有找到全通过方案时
明确标诊断，不放宽限制、不写用户确认、不生成视频。

## 8. 当前执行版本及冲突消解

以 `tour-rule-implementation.md` 的十二项规则为准。`tourContract.rulesetVersion` 必须为
`homeowner-tour-rules/2`；旧契约只可诊断，不自动改写历史源数据或继承批准。新增
`executionRules`、`trajectory` 检查。正式 coverage 只计算首次连续访问，不能沿用全片累计
覆盖报告。每个有意观看房间的进出预算必填。共享默认值、例外作用域、精确时间锁、
屏幕首个命中构图检查和真实播放失败的状态同步均按该执行表落实，Python/JS捕获入口一致。
