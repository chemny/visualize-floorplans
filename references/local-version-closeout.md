## 本阶段固化范围

布局使用状态、门型/门扇/把手/通行、固定子部件拉伸、浅色直铺纹理、踢脚线与收口、灯具/墙面风格联动、撤销重做与侧栏交互、组件能力索引、跨户型测试、导览路径/镜头和四阶段统一页面，均保留对应实现及回归入口。能力注册不代表逐个真实产品或所有户型通过验收。

制作顺序固定为：参观路线 → 实时镜头预演 → 装修渲染静音视频审阅 → 明确确认该视频后准备讲解、字幕和音乐并合成。参见 `tour-presentation-pages.md`。完整中间三维MP4可选，不能拿它替代装修效果视频。

合成报告保留选定音轨的路径及哈希、原始字幕区间、生成短句字幕、规范化输入任务、FFmpeg版本及参数、生成模块哈希、输入/输出帧数与时长。报告不复制私有声纹参考，不宣称跨硬件或不同工具版本的成品字节完全一致。

## 收尾检查入口

```text
python scripts/release_smoke.py --out NEW_EVIDENCE_DIRECTORY --node EXISTING_NODE --test-node-modules EXISTING_NODE_MODULES
```

该入口执行基础工具检查、引擎构建一致性、全部两层 Python 回归、组件索引和全部非浏览器 JavaScript 模块测试。几何检查显式传入已有 Three.js/esbuild 的 node_modules；缺少依赖时报告失败，不安装依赖。需要生成HTML与浏览器参数的 `test_sliding_editor.mjs` 属于页面测试，和 `_browser.mjs` 一起从模块收集中排除。没有 Node 时报告失败。

实际生成页面及跨户型浏览器检查分别使用已有 `--with-browser` / `--with-cross-layout` 参数，复用已有工具；报告区分 requested、blocked、not_applicable、fail、pass，不能把未执行写成通过。界面观感、设备表现和用户视频验收独立保留。

阶段收尾包括检查变更清单、确认引用完整、纳入本地 Git、记录提交及外部证据位置。历史测试源路径不作为新验收；不会自动发布、推送、换当前入口或清理历史案例。

## 明确保留的边界

- macOS / Codex 已使用；Windows远程Blender/OptiX执行已实测；Windows完整客户端、Claude Code、OpenClaw仍不等同于已验收。
- 新装修视频及讲解成片分别需要对应文件的用户确认；原三维视频的历史批准不转移到新渲染结果。
- 外部本地 TTS 在共享准备关卡通过后调用；本技能不控制任意第三方工具的直接调用。
- 字幕有页面短句覆盖和MP4可选轨/SRT能力；不宣称所有导出文件都已烧录字幕。
- 服务器保存、后台自动删除不在本阶段范围内。装修视频分支只使用任务明确指定的现有工具/远程服务，不自动安装模型。
- 当前客户布局、材质、路线、音视频和用户已确认的门开法均不因本次收尾调整。
